# Reproducibility Guide

Python 3.10+. The revised manuscript reports three kinds of numbers, and each
is regenerated by one script:

| In the paper | Script | Hardware | Outputs included |
| --- | --- | --- | --- |
| Derived constants of the theory; constant-versus-depth curve | `scripts/report_constants.py` (section 2) | CPU | printed |
| Matched fine-tuning at 130M parameters (Table 2, Appendix J) | `scripts/scale_study.py` (section 8) | one GPU, 16 GB or more | `paper/scale_study/` |
| Controlled study from scratch (Tables 3 and 4, Appendix K) | `scripts/controlled_study.py` (section 7) | CPU | `paper/controlled_study/` |

Sections 3 to 6 describe the general fine-tuning and evaluation harness
(RoBench-25, HarmBench, 370M). No number in the revised manuscript depends on
them.

## 1. Environment

```bash
# download the repository from the anonymous link, unzip it, and cd into it
python -m venv .venv && source .venv/bin/activate
pip install -e ".[training,dev]"
pytest -q
python scripts/regenerate_all.py --demo         # end-to-end smoke run on a random model
```

## 2. Constants first

```bash
python scripts/report_constants.py --config configs/lipmamba_130m.yaml
```

Read the three lines under "Readings".  If ℓ\* is < 1 or L_block is ≫ 10,
decide (docs/ICLR2027_AUDIT_RESPONSE.md §4) whether to change Δ_min, Δ_max,
λ_min, λ_max before spending GPU time.

## 3. Base checkpoints and data

```bash
python scripts/todo3_init_from_hf_mamba.py --base state-spaces/mamba-130m --revision <commit> \
    --out runs/lipmamba-130m_init.pt
python scripts/download_datasets.py --datasets wikitext103
python - <<'EOF'
from transformers import AutoTokenizer; import numpy as np, datasets
tok = AutoTokenizer.from_pretrained("EleutherAI/gpt-neox-20b")
for split in ("train", "validation"):
    ds = datasets.load_dataset("wikitext", "wikitext-103-raw-v1", split=split)
    ids = np.asarray(tok("\n".join(ds["text"]))["input_ids"], dtype=np.int32)
    ids.tofile(f"data_cache/wikitext103_{'val' if split=='validation' else 'train'}.bin")
EOF
```

RoBench-25: obtain the HiSPA authors' anonymised release, export to JSONL
(`abstract_id, abstract, question, answer`), tokenise prompts with the same
tokenizer.

## 4. Train

```bash
python scripts/finetune.py --config configs/lipmamba_130m.yaml --init-from runs/lipmamba-130m_init.pt
python scripts/finetune.py --config configs/lipmamba_370m.yaml --init-from runs/lipmamba-370m_init.pt
```

## 7. Controlled matched-training study (CPU, about two hours on four cores)

```bash
python scripts/controlled_study.py all --seeds 0 1 2 --jobs 4 --steps 3000 --n-eval 128 --iters 15
python scripts/controlled_study.py aggregate --dir runs/controlled
```

Trains a two-block selective SSM from scratch in a 2 x 2 design
{unconstrained, constrained} x {clean, adversarial training}, plus three
single-constraint ablations, and attacks every checkpoint with re-optimised
token triggers. Per-seed outputs and the summary of the reported run are in
`paper/controlled_study/`.

## 8. Matched-training study at 130M parameters (one GPU)

```bash
pip install transformers datasets
python scripts/scale_study.py run --model lip_at --tiny --out /tmp/smoke.json      # CPU smoke test, no download
python scripts/scale_study.py all --dir runs/scale --seeds 0 1 2 --paper-constants --ablations -- --preset a100
python scripts/scale_study.py aggregate --dir runs/scale
```

Every arm starts from the public `state-spaces/mamba-130m-hf` checkpoint and
is fine-tuned with the same data, optimiser, steps and seeds: unconstrained
and constrained, with clean and adversarial fine-tuning, plus
single-constraint ablations. Constrained arms use constants calibrated to
the checkpoint (`lipcal*`: each block's own spectral norms and eigenvalue
range, and quantiles of its clean step sizes and input norms) or the
paper's constants (`lip*`), which change the pretrained function
drastically at initialisation. The converted unconstrained model is checked
at start-up to compute the same logits as the `transformers` implementation.
The step projection is stored as one full matrix, so every arm has about
185M parameters. Attacks (random, zero-shot, gradient-guided token search
on the answer margin and on the state norm) are re-optimised against each
fine-tuned checkpoint. `notebooks/scale_study_colab.ipynb` runs the same
commands on Google Colab with results saved to Drive; `--preset l4` fits a
24 GB GPU. Results are written per run as JSON and summarised in
`summary.json` and `summary.md`. `notebooks/scale_study_kaggle.ipynb` does the same on Kaggle's two T4s. The outputs of the reported run are in
`paper/scale_study/` (see its README for what was and was not run).

## 9. What this repository does and does not regenerate

Regenerated by the released scripts, with per-seed outputs included:

* every derived constant of the theory and the constant-versus-depth curve (CPU);
* the controlled study from scratch (CPU, about two hours on four cores);
* the matched fine-tuning study at 130M parameters (one GPU; about one to two
  hours per arm on a 16 GB card). `paper/scale_study/README.md` lists which
  runs finished and which did not.

Not provided: fine-tuned checkpoints. The `--demo` paths of the harness in
sections 3 to 6 only validate the pipeline on a random model; their numbers
are meaningless as results.
